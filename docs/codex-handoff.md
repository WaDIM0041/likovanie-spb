## Перенос на Windows

Установите Git и Node.js LTS. В PowerShell выполните:

```powershell
git clone https://github.com/WaDIM0041/likovanie-spb.git
cd likovanie-spb
```

Откройте эту локальную папку в установленном Codex. Если папка уже клонирована, сначала сохраните свои локальные изменения, затем получите актуальную `main` через `git pull --ff-only`.

Переписка из браузера сама не становится контекстом нового задания. Первым сообщением локальному Codex отправьте:

> Прочитай docs/codex-handoff.md, docs/motion-design.md и docs/superpowers/plans/2026-10-14-stage-depth.md. Это продолжение работы над сайтом «Ликование». Проверь текущую ветку и состояние файлов, запусти локальный сайт и продолжай с учётом описанных требований. Не переделывай уже согласованную сцену без причины.

## Запуск и сборка

Готовые JS, CSS, фото и видео включены в Git: для просмотра переустанавливать Motion не нужно. Открывайте сайт через локальный HTTP-сервер из корня репозитория, а не через `file://`: новая 3D-сцена загружает локальный ES-модуль. Например, при установленном Python:

```powershell
py -m http.server 8000
```

Адрес: http://localhost:8000/. Сервер останавливается через Ctrl+C.

Для изменения исходников анимации сначала восстановите Framer Motion. Папка `vendor/motion` намеренно исключена из Git; обычного `npm install` в свежем клоне недостаточно.

```powershell
powershell -ExecutionPolicy Bypass -File scripts/restore-motion.ps1
npm ci --ignore-scripts
npm run build:motion
npm run check:motion
node scripts/build-site-motion.cjs
node scripts/build-webp-images.cjs
```

Восстановление нужно только один раз: скрипт сохраняет существующий `vendor/motion` и отказывается его перезаписывать. Motion зафиксирован на коммите `790a654dfef305307c566cf4e94d67a9f7a403c8`; локальная поправка типов применяется скриптом. Three.js зафиксирован на версии 0.180.0. Сборщик обновляет обе JS-сборки и версии ресурсов в корневом HTML. `build-webp-images.cjs` создаёт WebP-копии всех фотографий, подключённых на двух страницах, и сохраняет JPEG как запасной формат.

## Что уже реализовано

- Главный баннер с интерактивной деформируемой 3D-лентой, светом и частицами. Three.js загружается отдельно после немедленно видимой Canvas-сцены. Если WebGL недоступен или потерян, остаётся Canvas.
- Отдельная сцена с бирюзовым занавесом после баннера. В актуальной версии занавес раскрывается за 2,2 секунды после готовности и вступительного проявления фотографии; первым показан весь кадр `research/assets/041.jpg` с танцорами и логотипом на синем заднике.
- Автоматическая смена трёх фотографий каждые 6 секунд, ручной выбор и пауза. Мобильный блок уменьшен; элементы управления имеют отдельное место под фотографией.
- Все 57 используемых фотографий получают WebP-представление: браузер выбирает его первым, а `<picture>` сохраняет JPEG для совместимости. На первом экране приоритет только у главного кадра; остальные изображения загружаются по мере приближения.
- Плавное сияние, перелив и увеличение при наведении, скруглённые кнопки с заметными тенями, отступы вокруг номеров возрастных групп.
- Декоративные слои параллакса, стеклянные элементы управления, асимметричный ритм портретов и галереи на широком экране.
- Прожекторы, управляемые прокруткой: четыре пересекающихся конуса с плавным доворотом на тёмных и светлых разделах; в галерее свет закрепляется за фотографиями и виден между ними. На телефоне видны два луча, общая пауза и reduced motion останавливают движение.
- Короткая синемаграфия в разделе школы: большая часть репетиционного кадра неподвижна, движется выделенный исполнитель/платок. Слой создаётся из имеющегося видео; маска применяется в RGB. Файлы уже включены; пересоздание требует FFmpeg и Bash (`scripts/build-living-frame.sh`).
- Крупная надпись «ЛИКОВАНИЕ» во всю ширину футера с локальным шрифтом Cormorant Garamond и плавным переливом.

Актуальная палитра: чёрный, белый, бирюзовый и оранжевый. Изменения оформления и занавеса из `main` до `5399cb8` сохранены при добавлении прожекторов; соответствующие настройки возвращены из готовых JS-сборок в исходники. Для изменений анимаций редактируйте исходники, затем пересобирайте, чтобы настройки не расходились.

## Требования, которые нужно сохранить

Посетитель должен видеть выразительную сцену сразу после загрузки. Первая сценическая фотография важна пользователю: нельзя обрезать участников или закрывать логотип тяжёлым градиентом. Мобильная версия должна показывать саму фотографию, а не слишком высокий пустой блок.

Анимации имеют паузу, останавливаются вне экрана/в скрытой вкладке и учитывают `prefers-reduced-motion`. Обычная прокрутка касанием должна работать поверх Canvas. При reduced motion синемаграфия остаётся постером и не запрашивает видео. Автовоспроизведение может блокироваться браузером: остаются постер и кнопка включения.

Проверяйте ширины 320, 390, 700/768 и 1440 px: без горизонтального переполнения, перекрытий текста и резких переходов при наведении.

## Где вносить изменения

- `index.html` — опубликованная главная страница; `design/index.html` — дополнительный предпросмотр с другими относительными путями. Изменения общей разметки нужно синхронизировать.
- `design/style.css`, `design/stage.css` — оформление.
- `design/motion-source.js` — общий жизненный цикл Framer Motion и сцен.
- `design/ribbon-scene.js`, `design/ribbon-webgl.js` — Canvas/Three.js и взаимодействие.
- `design/stage-effects.js` — параллакс и синемаграфия.
- `design/scroll-spotlights.js` — управление лучами прожекторов от прокрутки.
- `scripts/build-site-motion.cjs` — сборка; готовые bundle-файлы вручную не редактировать.
- `scripts/build-webp-images.cjs` — повторяемая оптимизация JPEG в WebP и обновление разметки `<picture>`.
- `docs/motion-design.md` — подробности анимаций; `docs/content-transfer.md` — перенесённые материалы.

## Проверки и публикация

`npm run check:motion` проверяет модули Motion. Браузерные проверки лежат в `design/check-*.cjs`: spotlights, stage-depth, ribbon, scenes, curtain-timing, scroll-motion, transfer. Их настройка браузера различается: часть старых файлов указывает Windows-путь Chrome, новые проверки — Linux Chromium из облачной среды. Перед запуском на ПК настройте пути Playwright/браузера для этой машины. Не считайте ошибку пути браузера ошибкой сайта.

GitHub Pages публикует корень ветки `main`. Перед отправкой проверьте изменения и сборку, после отправки — успешный Pages workflow и публичную ссылку. В облачной среде рабочая ветка называлась `work`; для неё использовалось `git push origin HEAD:main`. В обычном клоне на ПК работайте с выбранной локальной веткой и проверяйте её перед push.

Формы пока готовят письмо и предлагают прямые контакты: отдельный сервер доставки заявок не подключён. Рабочий домен школы не перенесён. На реальном телефоне производительность WebGL отдельно не измерялась; проверки мобильных размеров и касаний выполнялись в Chromium.
